# 직결119

**경상북도 중증외상 최종치료 연결 콘솔** — 119 구급상황관리센터 상황요원을 위한 의사결정 보조 도구.

> 가장 가까운 응급실이 아니라, **재전원 없이 최종치료가 끝나는 병원**을 찾습니다.

Junction X Korea 2026 · 경상북도 트랙 (공공데이터 + AI로 지역 문제 해결)

---

## 문제

경상북도는 구미·경산·경주·포항을 제외한 대부분 지역이 응급의료 취약지입니다. 중증 다발성 외상 환자를
가장 가까운 응급실로 이송하면 응급실 진입은 되지만 **수술실·중환자실이 없어 다시 옮겨야 하는 재전원**이
발생합니다. 재전원은 수술 시작 시각을 크게 늦춥니다.

직결119는 공개 응급의료 데이터로 후보 병원의 **치료 사슬이 어디서 끊기는지** 계산해, 상황요원이
"왜 더 먼 병원으로 보내야 하는가"를 근거와 함께 판단하도록 돕습니다.

## 핵심 기능

| 화면 | 내용 |
| --- | --- |
| **치료 연속성** | 사고 시점부터 수술 시작까지 후보별 타임라인. 최근접 병원 경유 시 발생하는 재전원 지연(분)을 계산 |
| **후보 비교** | Top 3를 동일 항목·같은 행에서 직접 비교 (도착시간 / 역량 / 데이터 신선도 / 확인 위험 / 근거) |
| **지도 · 상세** | 사고지점과 후보 위치, 병원별 상세 카드와 응급실 직통번호 |

하단에는 **선별 과정**(전체 → 역량통과 → 제시 후보)과 **데이터 상태·한계**가 항상 표시됩니다.

## 안전 설계

이 도구는 의료 의사결정에 관여하므로, AI 환각과 공개데이터 불확실성을 코드 레벨에서 방어합니다.

- **AI는 후보를 만들지 않습니다.** 코드가 자격 필터를 통과시킨 병원 ID 집합 안에서만 Gemini가 순위를 정하며,
  응답은 Zod 스키마·허용 ID·중복·개수로 검증합니다.
- **AI 결과 하드 컷오프.** Gemini가 고른 1순위가 최속 후보보다 30분 넘게 느리면 응답을 폐기하고
  결정론 순위로 되돌립니다 (`src/lib/ai/gemini.ts`).
- **결정론 폴백.** 키가 없거나 검증에 실패하면 동일 입력에 동일 결과를 내는 규칙 기반 순위를 사용합니다.
- **`N1`(보유·사용불가)과 `정보미제공`은 가용으로 간주하지 않습니다.** 미확인 항목이 있으면
  `VERIFY_REQUIRED`로 분리해 전화 확인을 요구합니다.
- **탐색 한도(육로 120분)는 경로 API 성공 여부와 무관하게 적용됩니다.**
- **환자 위치·주소는 LLM에 전송하지 않습니다.** 이동시간 등 파생값만 전달합니다.
- 문구는 서버 측 코드 → 한국어 템플릿으로 렌더링해 LLM이 자유 서술하지 못하게 했습니다.

## 빠른 시작

사전 지식 없이 아래 절차만으로 실행됩니다. **API 키가 하나도 없어도 데모 스냅샷 모드로 전체 흐름이 동작합니다.**

```bash
git clone <repository-url>
cd junction-x-korea-2026
npm install
cp .env.example .env.local   # Windows: copy .env.example .env.local
npm run dev
```

http://localhost:3000 접속 → 영양군 추락 시나리오가 자동 실행됩니다.

> **요구 사항:** Node.js 20.9 이상, npm 10 이상.

### 환경변수

| 변수 | 필수 | 없을 때 동작 |
| --- | --- | --- |
| `NEMC_API_KEY` | 라이브 조회 시 | 데모 스냅샷 모드만 사용 가능 |
| `GEMINI_API_KEY` | 아니오 | 결정론 순위로 폴백 |
| `GEMINI_MODEL` | 아니오 | 기본 `gemini-2.5-flash` |
| `KAKAO_MOBILITY_REST_KEY` | 아니오 | 직선거리 기반 이동시간 추정 |
| `NEXT_PUBLIC_KAKAO_MAP_APP_KEY` | 아니오 | 좌표 기반 개략도로 대체 |

`NEMC_API_KEY`는 공공데이터포털에서 발급받은 **Decoding 키**를 넣습니다.

`GET /api/health`로 어떤 키가 비어 있는지 확인할 수 있습니다.

### 공개 API를 다루며 확인한 함정

실제 연동에서 문서와 응답이 다른 지점들이 있어 코드에 반영했습니다.

- 실시간 가용병상·중증질환 수용정보 오퍼레이션은 **`HPID` 파라미터를 무시**하고 첫 결과를 돌려줍니다.
  반드시 시도 단위로 받아 `hpid`로 클라이언트 조인해야 합니다 (병원명 문자열 조인 금지).
- 활용가이드는 `mkioskty1~28` 소문자로 표기하지만 실제 응답 필드는 **`MKioskTy1~28` 대문자**입니다.
- 기본정보의 `MKioskTy1~11`과 실시간 수용정보의 `MKioskTy1~28`은 **같은 이름이지만 의미가 다릅니다.**
  이 프로젝트는 `basicCapabilities` / `acceptance`로 네임스페이스를 분리했습니다.
- `hvidate`는 KST 14자리(`YYYYMMDDHHMMSS`)입니다. 로컬 타임존으로 파싱하면 UTC 서버에서 9시간 어긋납니다.

    comparison-table.tsx       Top 3 비교표

  lib/
    domain/schemas.ts          모든 계층이 공유하는 타입 계약
    domain/capabilities.ts     역량코드 → NEMC 필드 매핑
    domain/timeline.ts         타임라인 계산 (순수 함수)
    nemc/                      API 클라이언트 · 정규화 · 조인
    routing/                   카카오 경로 · 직선거리 폴백
    recommendation/            자격판정 · 결정론 순위 · 오케스트레이션

파이프라인: 반경 사전필터 → 예비평가 → 상위 후보만 경로조회 → `CONFIRMED`/`VERIFY_REQUIRED` 분리
→ Gemini 순위(검증) 또는 결정론 폴백 → 최근접 탈락 병원 계산.

## 배포

Vercel을 권장합니다. 서버 Route Handler에서 API 키를 다루므로 정적 호스팅(GitHub Pages)에는
기능형 배포가 불가능합니다.

1. GitHub 저장소를 Vercel에 연결합니다 (프레임워크 자동 감지: Next.js).
2. Project Settings → Environment Variables에 위 표의 키를 등록합니다. 값이 없으면 등록하지 않습니다
   (빈 문자열도 미설정으로 처리되지만 남기지 않는 편이 깔끔합니다).
3. `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`를 쓴다면 카카오 개발자 콘솔에서 허용 도메인을
   Vercel 도메인과 `http://localhost:3000`으로 제한합니다.
4. 배포 후 `/api/health`로 `missingKeys`를 확인합니다.

발표 백업으로 로컬 `npm run build && npm start`를 준비해 두는 것을 권장합니다.
데모 스냅샷 모드는 외부 API 없이 동작합니다.

## 한계와 면책

- **본 도구는 의료행위나 병원 배정을 대체하지 않습니다.** 표시된 모든 후보는 이송 전 전화 확인이 필요합니다.
- 공개된 `Y` 값은 **수용 확약이 아닙니다.** 기관이 입력한 시점의 상태 표시일 뿐입니다.
- "확인 위험" 등급은 임상적으로 검증된 수용 확률이 아니라, **데이터 경과시간·누락 정도**에 기반한 정성 등급입니다.
  환자별 수용 결과 데이터가 공개되지 않아 확률 모델은 만들 수 없습니다.
- 타임라인의 병원 내 처치·전원준비 시간은 후보 비교를 위한 **도식용 고정 가정값**이며 실제 소요시간이 아닙니다.
- 헬기 이송은 범위에서 제외했습니다 (육로만).
- `src/data/demo-hospitals.json`의 병원은 **합성 데이터**이며 실존 기관의 상태가 아닙니다.
